生成日期：2026-06-02

一、项目定位

本项目可定位为“霍格沃茨魔法即时通讯 + AI 角色扮演 + 学院成长养成”的综合网页应用。

核心体验不是传统游戏官网，而是一个沉浸式魔法社交系统：
1. 用户以“巫师”身份进入系统。
2. 可以和哈利波特世界观角色私聊或群聊。
3. 可以在魔法圈发布动态。
4. 可以参与学院杯、每日任务、答题、决斗、魁地奇等成长玩法。
5. 可以通过金库、对角巷、有求必应屋形成货币、商店、家园、宠物养成闭环。

四、推荐技术架构

1. 前端技术

推荐方案：
- React + TypeScript + Vite。
- 状态管理：Zustand。
- 路由：React Router。
- UI 动效：Framer Motion。
- 图标：Lucide 或自定义魔法主题图标。
- 样式：Tailwind CSS 或 CSS Modules。
- 实时通信：WebSocket 或 SSE。

前端页面结构：
- /login 登录。
- /register 注册。
- /forgot-password 忘记密码。
- /app/owl 猫头鹰聊天页。
- /app/circle 魔法圈。
- /app/house-cup 学院杯。
- /app/room 有求必应屋。
- /app/diagon-alley 对角巷。
- /app/vault 古灵阁金库。
- /app/settings 设置。
- /app/profile 个人资料。

2. 后端技术

推荐方案：
- Node.js + NestJS 或 Fastify。
- 数据库：PostgreSQL。
- 缓存：Redis。
- 对象存储：Cloudflare R2、S3 或阿里云 OSS。
- AI 服务：OpenAI 兼容接口、Claude、Gemini 或本地模型代理。
- 鉴权：JWT + Refresh Token。
- 实时消息：WebSocket Gateway 或 SSE。

3. 部署方案

开发环境：
- 前端 Vite dev server。
- 后端 Node server。
- PostgreSQL 本地或 Docker。
- Redis 本地或 Docker。

生产环境：
- 前端部署到 Vercel、Cloudflare Pages 或 Nginx。
- 后端部署到云服务器、Railway、Render、Fly.io 或 Docker。
- 数据库使用 Supabase、Neon、RDS 或自建 PostgreSQL。
- Redis 使用 Upstash、云 Redis 或自建。
- 图片存储使用 R2、S3 或 OSS。

六、关键业务流程

1. 注册流程

1）用户输入邮箱、密码、可选推荐码。
2）后端校验邮箱格式和密码长度。
3）生成用户。
4）生成钱包。
5）生成用户资料。
6）如果有推荐码，绑定推荐关系。
7）发送邮箱验证邮件。
8）进入新手引导。

2. 登录流程

1）用户输入邮箱和密码。
2）后端验证密码。
3）返回 access token 和 refresh token。
4）前端加载用户资料、钱包、角色列表、任务状态。
5）进入主界面。

3. 聊天流程

1）用户选择角色。
2）前端创建或读取会话。
3）用户发送消息。
4）后端保存用户消息。
5）后端组装角色提示词、历史摘要、最近消息。
6）调用 AI 模型。
7）流式返回角色回复。
8）保存 AI 消息。
9）根据规则扣除额度或金币。

4. 魔法圈发布流程

1）用户输入动态内容。
2）可选上传图片。
3）后端内容审核。
4）保存动态。
5）如果是每日任务，更新任务进度。
6）返回新动态列表。

5. 学院任务流程

1）用户打开学院杯。
2）读取每日任务。
3）完成布告栏任务或写论文。
4）发放学院分和金币。
5）写入积分流水。
6）刷新学院排行榜。

6. 对角巷购买流程

1）用户进入对角巷。
2）选择商店。
3）查看商品详情。
4）点击购买。
5）后端校验余额、库存、限购。
6）扣除金币。
7）写入订单。
8）发放物品到背包。
9）写入金币流水。
10）前端提示购买成功。

7. 龙蛋孵化流程

1）用户在神奇动物园购买龙蛋。
2）龙蛋进入背包。
3）用户进入有求必应屋。
4）如果房间已解锁，可以选择孵化龙蛋。
5）创建 pet 记录，阶段为 egg。
6）倒计时完成后变为 baby。
7）用户每日喂食。
8）每次喂食消耗 1 个苹果条。
9）成长值达到要求后变为 adult。

8. 金库签到流程

1）用户打开金库。
2）后端检查今天是否已签到。
3）未签到则发放金币。
4）已签到则提示明天再来领取。
5）记录签到日志。

9. 兑换码流程

1）用户输入 CARD KEY。
2）后端校验兑换码是否存在、过期、达到使用次数。
3）校验该用户是否已使用。
4）发放金币或道具。
5）记录兑换。
6）返回结果。

3. 登录页：九又四分之三站台动画方案

参考方向：
网易云音乐曾做过霍格沃茨相关彩蛋：音乐播放到约 40 秒后出现送信猫头鹰飞过，评论图标会变成一封带有“九又四分之三”提示的信件，并进一步引导用户发现评论区彩蛋。

本项目可以把这个思路改造成“登录即穿过九又四分之三站台”的沉浸式入口。

登录页主题：
- 标题：九又四分之三站台。
- 副标题：出示你的车票，进入猫头鹰邮局。
- 背景：国王十字车站、砖墙、昏黄车站灯、远处蒸汽、霍格沃茨特快轮廓。
- 核心视觉：砖墙中间挂着 Platform 9¾ 标牌。
- 表单样式：录取通知书、车票或羊皮纸卡片。

登录页文案：
- 邮箱输入框：你的魔法邮箱。
- 密码输入框：通行密语。
- 登录按钮：穿过墙壁。
- 注册入口：还没有车票？领取入学信。
- 忘记密码：弄丢了通行密语？

默认待机动画：
- 砖墙轻微呼吸式暗光。
- Platform 9¾ 标牌有微弱金光。
- 背景有轻微蒸汽飘动。
- 每隔一段时间有猫头鹰剪影飞过。
- 信封图标偶尔闪烁，提示用户这是进入魔法世界的入口。

输入阶段动画：
- 用户聚焦邮箱或密码时，羊皮纸边缘亮起。
- 输入密码时，魔法墨水或星点随光标出现。
- 表单校验错误时，砖墙轻轻震动。

登录成功动画：
1）用户点击“穿过墙壁”。
2）按钮进入检查状态，显示“正在核验车票...”。
3）猫头鹰叼着信封从屏幕侧边飞过。
4）行李车从画面下方推向砖墙。
5）砖墙中心出现金色裂缝或旋涡。
6）Platform 9¾ 标牌发光。
7）墙体向两侧打开，或以镜头推进方式穿过砖墙。
8）短暂白光、蒸汽、火车汽笛。
9）进入主应用“猫头鹰邮局”。

登录失败动画：
- 砖墙反弹或轻微摇晃。
- 文案：墙壁没有让你通过，请检查邮箱或密码。
- 按钮恢复为“穿过墙壁”。
- 不要清空用户已输入的邮箱。

注册成功动画：
- 猫头鹰投递录取通知书。
- 通知书展开，显示“欢迎来到猫头鹰邮局”。
- 再跳转到新手引导或主界面。

忘记密码动画：
- 变成“找回通行密语”的信件流程。
- 用户输入邮箱后，猫头鹰飞出送信。
- 文案：找回信已经交给猫头鹰，请留意邮箱。

前端实现建议：
- 使用 React + Framer Motion 实现场景转场。
- 使用 CSS animation 实现猫头鹰、蒸汽、标牌发光。
- 使用 transform: translate/scale/rotate 实现行李车推进。
- 使用 clip-path、mask-image 或伪元素实现砖墙裂开。
- 使用 local state 管理登录状态。

动画状态设计：
- idle：默认站台待机。
- typing：用户正在输入。
- checking：正在核验账号。
- failed：登录失败。
- entering：登录成功，穿墙动画播放中。

示例状态逻辑：

async function handleLogin() {
  setLoginState("checking");
  const result = await login(email, password);

  if (!result.ok) {
    setLoginState("failed");
    return;
  }

  setLoginState("entering");
  await wait(1200);
  navigate("/app/owl");
}

建议动画时长：
- 登录按钮检查态：300 到 500 毫秒。
- 猫头鹰飞过：600 到 900 毫秒。
- 行李车冲向墙：500 到 800 毫秒。
- 砖墙打开或穿越：700 到 1200 毫秒。
- 总跳转时间：1.2 到 2 秒。

注意事项：
- 不要直接复制网易云或其他产品的素材。
- 可以借鉴“猫头鹰飞过、信封提示、九又四分之三暗示、进入隐藏世界”的交互结构。
- 所有图形建议自绘或使用自有素材。
- 动画必须可跳过，避免用户每次登录等待太久。
- 移动端应简化粒子和背景动画，优先保证流畅。

十四、结论

该项目最适合做成“AI 角色聊天 + 魔法学院生活模拟 + 轻度经营养成”的网页应用。

核心闭环应为：

任务和学院杯带来每日目标；
金库和对角巷形成经济系统；
有求必应屋和养龙提供长期养成；
推荐官计划和魔法圈提供增长与社交传播。

第一版不要一次性做完所有复杂系统，应先打通登录、聊天、金库、商店、任务、动态这六个关键模块。只要这六个模块稳定，后续的决斗、魁地奇、养龙和家园都可以逐步扩展。

5.2 登录页动画状态机
----------------------------------------

  idle -> typing -> checking -> entering(穿墙1.2s) | failed(震动3s)
  idle:砖墙光效+猫头鹰  typing:羊皮纸发光+魔法粒子  checking:猫头鹰叼信+行李车  entering:墙体裂开+白闪+蒸汽
  实现: Framer Motion AnimatePresence + CSS keyframes + clip-path

============================================================
十一、风险评估
============================================================

  版权: 哈利波特角色有风险, 替代方案=原创魔法世界观
  AI安全: Prompt injection防护 + 内容过滤 + 越狱检测
  数据安全: bcrypt + JWT短时效 + 限流 + CSP + Prisma防注入
  未成年人: 消费限制(单次<=50元,月<=200元)
